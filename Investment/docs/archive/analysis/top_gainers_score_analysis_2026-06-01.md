# 直近1カ月の値上がり銘柄とスコア推移分析

## 結論

投資判断支援システムの内部スコアは、売買検討可能な値上がり上位50銘柄のうち36銘柄を候補化し、さらに8銘柄を50点以上の監視対象として捉えていた。内部評価では44 / 50銘柄（88%）を認識できていた。

一方、`trade_signal_log` に実際の通知対象として残った銘柄は、分析期間前の通知を含めても1 / 50銘柄（2%）だった。主因は、候補をスコア順で全体3件に絞ってから通知ログへ渡す実装である。内部候補36銘柄のうち通知されなかった35銘柄は、いずれも候補内順位が4位以下だった。

したがって、現状は「スコアリングが上昇を認識できない」というより、「認識した銘柄を通知・追跡へ十分に残せない」ことが大きな課題である。

## 集計条件

- 集計実施日: 2026-06-01
- JP基準日: 2026-06-01
- US基準日: 2026-05-29（日本時間2026-06-01時点でDBに保存済みの最新US営業日）
- 直近1カ月: システム実装と同じ20営業日騰落率 `return_20d`
- 対象市場: JP / US
- 選定母集団: 最新スナップショットがあり、アクティブかつ除外対象外で、現在の流動性フィルタを満たす銘柄
- 流動性フィルタ: MA200あり、株価下限、売買代金下限、判明時の時価総額下限、直近約50暦日で20取引日以上
- 売買検討可能な母集団: 3,155銘柄（JP 1,132、US 2,023）

分析はローカルDB `Investment/investment_support/data/investment.db` の保存データに基づく。投資助言ではない。

なお、50銘柄の選定では最新時点の流動性条件を使っている。期間初日に売買可能だったが最新時点では条件を外れた銘柄、または期間途中から条件を満たした銘柄を厳密に再現するバックテストではない。現行システムが直近の上昇銘柄をどの程度認識していたかを見る診断として扱う。

## 無加工上位50件の問題

流動性条件をかけずに全アクティブ銘柄から上位50件を取ると、全件がUS銘柄となり、20営業日騰落率は最小でも+1,711.0%、最大で+2,754,499,969.6%だった。OTC、低位株、極端に薄い銘柄、株式併合等のコーポレートアクション影響が疑われる値が中心で、投資システムの捕捉性能評価には適さない。

## 捉えられた理由

内部候補化のみ35銘柄の最大スコア中央値は78点、Trend中央値は100点、最良パターン適合度中央値は80点だった。値上がりが継続した銘柄では、以下の要素が機能している。

- MA200の上昇、MA整列、終値のMA25上方維持によるTrend評価
- 52週高値への接近、出来高増加、RSI適正帯によるPattern A評価
- MA25への押し目と反発によるPattern B評価
- 最低売買代金と取引日数による薄商い銘柄の除外

代表例:

- `4392 FIG`: 2026-05-14に69点で候補化。その後も+165.1%上昇し、最大78点。
- `6976 太陽誘電`: 2026-05-14に84点で候補化。その後+132.4%上昇。
- `UMAC`: 2026-05-11に64点で候補化。その後+107.2%上昇し、最大84点。
- `DELL`: 2026-05-11に80点で候補化。その後+70.4%上昇し、最大83点。

## 捉えられなかった理由

### 1. 通知対象が全体3件に限定される

`signal.max_candidates_per_pattern = 3` という設定名だが、実装ではパターン別3件ではなく、全候補をスコア順に並べた後の全体上位3件だけを通知ログへ渡す。内部候補化のみ35銘柄はすべて候補内順位4位以下で、通知対象にならなかった。

### 2. 攻めモードの最低80点で監視止まりになる

50点以上の監視8銘柄のうち5銘柄は、攻めモードの `min_final_score = 80` に届かなかった。特に `ASTC` は72点で監視止まりだったが、監視入り後も+69.2%上昇した。

### 3. パターン適合度60点未満で候補化されない

50点以上の監視8銘柄のうち3銘柄は、主要パターン適合度が60点未満だった。`REPL`、`KEEL`、`SNOW` は上昇しているものの、ブレイクアウト・押し目・サポート反発のいずれにも十分に適合しなかった。

### 4. 急騰が先行し、長期トレンドを作る前に上がる

最大スコア50点未満の6銘柄は、最大スコア中央値44点、Trend中央値25点だった。`VCIG` や `CODX` のような短期急騰は、MA200やMA整列を重視する現行ロジックでは初動を捉えにくい。これは誤検知抑制とのトレードオフであり、単純に閾値を下げるべきとは限らない。

## 運用上の注意

### スコア履歴が日次で連続していない

`daily_signals` の保存日はJPが6日、USが8日だけだった。スコア推移は参考になるが、毎営業日の連続時系列としては扱えない。

### 通知ログに重複がある

`trade_signal_log` は78行あるが、`signal_date + ticker + market` の重複を除くと37件だった。バッチ再実行時に同一通知が追加保存されるため、通知件数、ペーパートレード、成績集計を歪める可能性がある。

### `running` のまま残ったバッチログがある

`batch_run_log` には `running` のまま残った行が15件あった。内訳は `morning_all` 7件、`evening_jp` 5件、`monthly` 3件。ヘルス表示や障害判定では、一定時間を超えた `running` を失敗扱いにする必要がある。

### 2026-06-01のJP最新評価は警戒モード

2026-06-01のJP夜バッチ時点ではUS当日データが未確定のため、市場環境は `caution`。最新日のJP候補は監視へ降格される。JPの捕捉評価では、期間中の通常モード日も含めて判定した。

## 改善優先度

1. `trade_signal_log` に `(signal_date, ticker, market)` の一意制約または保存前重複チェックを追加する。
2. 通知対象を「全体上位3件」だけでなく、内部候補一覧、監視リスト、前日比スコア上昇銘柄としてダッシュボードに残す。
3. `max_candidates_per_pattern` の名前と実装を一致させる。パターン別上限にするか、`max_candidates_total` に改名する。
4. `daily_signals` を毎営業日確実に保存し、スコア推移の連続性を確保する。
5. US銘柄マスタに取引所・証券種別フィルタを追加し、OTC、権利、清算銘柄、極端な低位株、コーポレートアクション影響を分析母集団から除外する。
