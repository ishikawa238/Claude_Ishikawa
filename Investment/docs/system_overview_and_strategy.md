# 投資判断支援システム — システム概要と投資戦略

> **免責**: 本システムは投資助言や利益保証を行うものではありません。検出される候補は「検討対象」であり、注文指示ではありません。最終的な売買判断と発注はユーザー自身の責任で行ってください。

最終更新: 2026-07-02

---

## 1. システムの位置づけ

日本株・米国株を対象とした**実行規律補助システム**です。全自動売買ではなく、日次の価格データからテクニカル指標を計算し、買いパターンの検出・保有銘柄の損切り判定・Slack通知を自動化します。ユーザーが最終判断を下す前提で設計されています。

### 主な役割

| 領域 | システムが行うこと | ユーザーが行うこと |
|------|-------------------|-------------------|
| 銘柄探索 | 全銘柄スクリーニング、スイング条件の検出 | 候補の最終選定 |
| リスク管理 | 損切りライン・推奨投入額の算出、市場環境フィルタ | 実際の注文・ポジションサイズの確定 |
| 出口 | 利確目安・時間減衰目標の通知 | 売却タイミングの判断 |
| 記録 | シグナル履歴・ペーパートレード・実績の蓄積 | トレード結果の確認・補正 |

### 対象市場とデータ規模

- **日本株**: 約3,600銘柄（価格は yfinance、財務・決算は J-Quants 任意）
- **米国株**: 約51,000銘柄（価格は EODHD）
- **除外対象**: ETF、REIT、優先株、OTC、流動性極低銘柄など

## 2. システム構成（概要）

### 2.1 データフロー

```
外部API（EODHD / yfinance / J-Quants / moomoo OpenD）
  ↓
price_history / index_snapshot（SQLite）
  ↓
technical_snapshot（MA, EMA, RSI, ATR, MACD 等）
  ↓
market_environment（通常 / 警戒 / 全面警戒）
  ↓
daily_signals → trade_signal_log（シグナル検出 → エントリーセット）
  ↓
Slack通知 + Webダッシュボード（127.0.0.1:5100）
```

### 2.2 定期バッチ

| 時刻 | バッチ | 内容 |
|------|--------|------|
| ログオン時 | `order_server` | Webダッシュボード起動 |
| 毎日 20:30 | `batch_evening_jp` | JP株価取得 → テクニカル → シグナル → Slack夜通知 |
| 毎日 07:30 | `batch_morning_all` | US株価取得 → JP+US統合 → Slack朝通知 |
| 毎時 | `batch_watchlist_hourly` | moomooお気に入りスイング監視 + 保有損切り/利確アラート |
| 毎月1日 08:00 | `batch_monthly` | 銘柄マスタ更新 + 月次レポート |

### 2.3 主要な Web 画面

| URL | 用途 |
|-----|------|
| `/report` | 保有状況・シグナル履歴・チャート・今日のアクション |
| `/rules` | 買ってよい条件・資金管理・出口ルールの確認 |
| `/settings` | 資金・シグナル・スクリーニング・戦略モードの変更 |
| `/screening` | 全銘柄スクリーニング・ブックマーク・Prompt Builder 連携 |
| `/performance` | 総資産推移・S&P500比較・トレード実績 |
| `/prompt-builder` | 売却・購入判断の相談用プロンプト生成 |

## 3. 投資戦略の全体像

本システムは **2つの戦略モード** を `config.json` の `strategy_mode` で切り替えられます。

| モード | 目的 | 保有上限 | リスク/銘柄 | 利確の考え方 |
|--------|------|----------|-------------|--------------|
| `defensive`（既定） | 短期〜中期の利益を積み上げる守り戦略 | 3銘柄 | 口座の2%固定 | 早めの分割利確（+0.5R/50% 等） |
| `offensive` | 2倍・3倍株を狙う攻め口座 | 5〜8銘柄 | 1銘柄最大20% | +1R/+3R/+5R 各20%、残り40%を大化け枠 |

詳細は [archive/offensive_strategy.md](archive/offensive_strategy.md)（アーカイブ）を参照。`defensive` に戻せば現行互換の挙動になります。

## 4. コア戦略

### 4.1 EMA押し目スイング（既定）

| 市場 | 戦略名 | 株価帯（目安） | 検出条件 |
|------|--------|--------------|----------|
| US | `moomoo_swing` | $10〜$50 | EMA25>EMA75 + ダイナミックRSI + MACD反転/GC |
| JP | `swing_jp` | ¥300〜¥3,000 | 同上 |

### 4.2 新高値ブレイクアウト（追加）

| 市場 | 戦略名 | 検出条件 |
|------|--------|----------|
| US | `breakout_us` | 60日高値更新 + 出来高≥20日平均の1.5倍 |
| JP | `breakout_jp` | 同上 |

`config.json` の `breakout.enabled: false` で無効化可能（コード既定は有効）。通知枠はスイング優先（例: 全体3件のうちブレイクアウト最大1件）。

## 5. 旧セクション — シグナル段階（スイング）

- **watch（監視）**: EMA25 > EMA75 — 上昇トレンド継続中
- **candidate（検討候補）**: watch条件 + ダイナミックRSI + MACD反転またはゴールデンクロス確認

### お気に入り毎時監視

moomoo「All」お気に入り銘柄を市場開場中に毎時スキャンし、上記3条件（MACDはヒスト反転+GC両方）を満たした銘柄を Slack 即時通知します。

## 5. 市場環境フィルタ

指数の MA25 を基準に、新規買い候補の発信を制御します。

#### 市場別判定（既定）

シグナル検出とエントリーセット計算には、**対象市場の指数だけ**を使います（`market_filter.per_market_mode: true`）。
米国株の下落で日本株の候補まで止まる「巻き添え停止」を防ぐための措置です。

| 対象 | 判定に使う指数 | 通常（発信する） | 警戒（停止） |
|------|--------------|----------------|-------------|
| 日本株 | 日経平均のみ | 日経平均 ≥ MA25 | 日経平均 < MA25、または判定不能 |
| 米国株 | S&P500 のみ | S&P500 ≥ MA25 | S&P500 < MA25、または判定不能 |

**判定不能**（安全側の警戒扱い）になるのは次の場合です。

- 指数の MA25 が未計算（MA25 が NULL の行は比較に使わない）
- 使える指数データが `market_filter.index_max_stale_days`（既定 5 日）より古い

当日の指数データがない場合は、鮮度の範囲内であれば直近営業日の値を使います。
また夜バッチ（日本株のみ）でも、米国側の値が未確定なら直近データで補完するため、
全体モードが警戒に固定されることはありません。

#### 全体モード（通知表示・レポート統計用）

`market_environment.mode` には従来どおり両指数を組み合わせた全体モードを保存します。
Slack 通知のヘッダー表示とレポート統計に使われ、シグナルの可否判定には使いません。

| モード | 条件 |
|--------|------|
| 通常（normal） | 日経平均 ≥ MA25 かつ S&P500 ≥ MA25 |
| 警戒（caution） | いずれか一方が MA25 未満、または判定不能 |
| 全面警戒（full_caution） | 両方が MA25 未満 |

`market_filter.per_market_mode: false` にすると、市場別判定をやめて全体モードでシグナルを
制御する従来動作に戻ります。

**保有銘柄の損切り判定は市場環境に関わらず常時実行**されます。

## 6. エントリーと資金管理

### 6.1 エントリーセット（候補通知時に算出）

| 項目 | 計算方法 |
|------|---------|
| エントリー価格 | 当日終値（翌日寄付想定） |
| 損切りライン | サポート下（優先）または ATR14 × 2 |
| 利確目安（新規候補） | リスクリワード 2:1（参考表示） |
| 推奨投入額 | `総資金 × 2% ÷ 損切り幅(%)` を基本に、`総資金 ÷ 有効保有枠` を上限 |

### 6.2 リスク停止ルール

`config.json` の `risk_control` で設定:

- **月間損失停止**: 月間確定損失が `monthly_loss_stop_pct`（既定6%）に達したら新規買い停止
- **連続損失停止**: 損失トレードが `max_consecutive_losses_before_pause`（既定3回）連続したら停止

### 6.3 RSスコア（相対強度）

`config.json` の `rs_score` セクションで制御:

- **記録**: 126営業日リターンをベンチマーク（JP=N225, US=S&P500）と比較し、市場内百分位を `rs_score`（0〜100）として `technical_snapshot` に保存
- **ダイナミックRSI**: RSスコアが高い銘柄ほど RSI 上限を緩和（例: RS100 → RSI≤50）
- **足切り**: `filter_enabled: true` で `min_rs_score`（既定70）未満をスクリーニング除外（**既定はOFF**）

```json
"rs_score": {
  "enabled": true,
  "filter_enabled": false,
  "min_rs_score": 70,
  "dynamic_rsi_enabled": true
}
```

### 6.4 投資目標（検証用）

```json
"investment_goal": {
  "monthly_deposit_jpy": 10000,
  "target_monthly_return_pct": 15.0
}
```

月次レポートでは入金分を除いたリターンを計算し、目標との差を確認します（利益保証ではありません）。

## 7. 出口戦略

### 7.1 損切り（最優先）

- 損切りライン到達時は Slack で最優先通知
- 省略時は `entry_price × 0.92`（-8%）を自動設定
- 攻めモードでは損切りラインの引き下げを原則ブロック

### 7.2 保有銘柄の利確 — exit_simple（守りモード）

時間減衰型の利確目標:

| 保有日数 | 利確目標 |
|----------|----------|
| 0〜30日 | +20% |
| 31〜60日 | +15% |
| 61〜90日 | +10% |
| 91日〜 | +5% |

目標到達時: EMA25>EMA75・MA25上・RSI≤70 を満たせば2株以上は半分売却・1株は温存。満たさなければ全売却推奨。

### 7.3 値動きタイプ別の分割利確 — take_profit（攻め/守り）

利確は値動きタイプ（I: ブレイクアウト / II: トレンドフォロー / III: 中長期）に応じて R 倍率で段階的に売却します。

| モード | 第1利確 | 第2利確 | 第3利確 | 残り |
|--------|---------|---------|---------|------|
| defensive | +0.5R / 50% | +1R / 30% | +2R / 20% | — |
| offensive | +1R / 20% | +3R / 20% | +5R / 20% | 40% 大化け枠（MA25/MA50トレーリング） |

詳細は [archive/take_profit_rules_by_price_action.md](archive/take_profit_rules_by_price_action.md)（アーカイブ）を参照。

### 7.4 攻めモードの追加ルール

- **買い増し**: 含み益+10%以上・MA25維持・出来高維持・直近高値再突破時のみ（ナンピン禁止）
- **段階撤退**: MA25割れで短期回収枠売却、MA50割れで大化け枠も手仕舞い検討
- **銘柄選定**: S/Aランク・スコア80以上・52週高値更新・出来高2倍などで厳選

## 8. 検証と運用の流れ

推奨される運用開始手順:

1. `paper_mode.enabled = true` で最低1か月ペーパートレード
2. `backtest_signals` で過去シグナルの期待値を確認
3. `/rules` で投資ルールを理解
4. Slack通知のテスト送信を確認
5. 実資金投入前に `total_capital_jpy` / `total_capital_usd` を実際の運用資金に合わせる

ペーパートレードはシグナル当日の終値ではなく**翌営業日の始値**で仮想約定し、約定当日は利確・損切り判定を行いません。
