投資判断支援システム 修正計画（更新版）
更新日: 2026-05-08
前回: 2026-04-30

目的
====
現状の投資判断支援システムを、初心者が誤解なく使える「実行規律補助システム」に近づける。
特に以下を重視する。

1. 誤ったシグナルや過大な推奨が出ないこと
2. 初心者が重要情報を見落とさないこと
3. Slack通知が読みやすく、行動に直結すること
4. ダッシュボードが「今日何をすべきか」を即座に伝えること
5. 文書と実装の食い違いをなくすこと


完了済み（参考）
================
- 警戒モード時の candidate → watch 自動降格（signal_detector.py L88）
- 推奨投入額の上限制御: 総資金キャップ・同時保有上限キャップ・損切り幅フィルタ
- 推奨投入額に既存保有数を考慮（entry_calculator.py: _count_open_holdings）
- 価格取得全件失敗時にテクニカル計算・シグナル検出をスキップ（B1）
- Slack通知失敗でバッチ全体がfailedになるのを防止（B2）
- テスト全件パス（216テスト OK / 2026-05-08時点）
- バックテスト機能（backtester.py / test_backtester.py）
- ペーパートレード機能（paper_trading.py / バッチ統合済み）
- 端株対応（moomoo証券の端株取引を前提に100株単位制約を除去）


優先度A: 安全性・信頼性
========================

A-1. Slack通知の長さ制御
------------------------
影響度: 高

現状:
- 候補3件 + Near-miss 3件 + 保有5件 + LLM 3プロバイダで通知が非常に長くなる。
- 長すぎると読み飛ばされ、損切り警告を見逃すリスクがある。

修正方針:
- 損切り警告・アクション項目を冒頭に固定し、詳細はダッシュボードリンクに誘導する。
- LLMフィードバックは要約（2-3行）のみ掲載し、全文はダッシュボードに移す。
- Near-miss は最大2件に削減するか折りたたみ扱いにする。

対象ファイル:
- src/notifier.py
- scripts/order_server.py

確認観点:
- 損切り警告が通知の先頭3ブロック以内に必ず表示される。
- Slackモバイルで1スクロール以内にアクション項目が収まる。


A-2. 損切り到達時のアクション導線
---------------------------------
影響度: 中

現状:
- 🚨で警告するが「何をすべきか」の具体的ガイダンスがない。
- 初心者は警告を見ても行動に移れない可能性がある。

修正方針:
- 損切り到達通知に「成行売りを検討してください」等の一言を添える。
- 保有枠満杯の警告（_warn_at_capacity）も通知に反映する。

対象ファイル:
- src/notifier.py


A-3. バッチ並行実行の保護
-------------------------
影響度: 中

現状:
- 夜バッチと朝バッチが重なった場合のDB書き込み競合保護がない。
- WALモードで読み取りは安全だが、upsert の競合リスクが残る。

修正方針:
- ファイルロック（fcntl / msvcrt）またはDB内ロックテーブルで排他制御する。
- 既にバッチ実行中なら2重起動をスキップしてログに記録する。

対象ファイル:
- scripts/batch_evening_jp.py
- scripts/batch_morning_all.py


A-4. バッチタイムアウト
-----------------------
影響度: 中

現状:
- 外部API（EODHD, yfinance, J-Quants）の応答が返らない場合、バッチが無期限にハングする。

修正方針:
- バッチ全体にタイムアウト（例: 30分）を設ける。
- 個別API呼び出しにも適切なタイムアウトを確認する。

対象ファイル:
- scripts/batch_evening_jp.py
- scripts/batch_morning_all.py


A-5. signal_detector の None 値の明示処理
-----------------------------------------
影響度: 中

現状:
- テクニカル値が None の場合、暗黙的に条件不成立になる。
- 「データ不足で判定不能」と「条件未達」の区別がつかない。

修正方針:
- None 値の条件にはログで「データ不足」と明示する。
- 通知にも「データ不足のため一部条件は判定保留」と表示する。

対象ファイル:
- src/signal_detector.py
- src/notifier.py


優先度B: UX改善（初心者向け）
==============================

B-1. ダッシュボードのアクション優先表示
---------------------------------------
影響度: 高

現状:
- /report が1画面に全情報を詰め込みすぎて、初心者には「今すぐ見るべきこと」が埋もれる。

修正方針:
- /report の最上部に「今日の行動」セクションを固定表示する。
  - 損切り対象あり → 最優先で確認
  - 警戒モード → 新規買い停止中
  - 通常モード → 検討候補あり/なし
  - 保有枠の状況（残りN枠）
- 詳細は折りたたみにして、初期表示をシンプルに保つ。

対象ファイル:
- scripts/order_server.py


B-2. 見送り理由の表示
---------------------
影響度: 中

現状:
- 条件を満たした理由はある程度表示されるが「なぜ見送るべきか」が弱い。

修正方針:
- 以下の理由を通知・ダッシュボードに出す。
  - 警戒モードのため新規買い停止
  - 損切り幅が広すぎる（高ボラティリティ）
  - 推奨投入額が資金に対して過大
  - 保有枠が満杯（_warn_at_capacity）
  - 決算発表が近い
  - データ不足で判定保留

対象ファイル:
- src/notifier.py
- scripts/order_server.py


B-3. データ鮮度の表示
---------------------
影響度: 中

現状:
- ダッシュボードにデータ取得時刻の表示がない。
- バッチがいつ走ったか分からず、表示価格が古い可能性に気づけない。

修正方針:
- ダッシュボード・Slack通知の両方に「データ取得時刻」を表示する。
- batch_run_log の最新レコードを参照する。

対象ファイル:
- scripts/order_server.py
- src/notifier.py


B-4. 推奨投入額の通貨合算・株数表示
------------------------------------
影響度: 中

現状:
- JP銘柄は円、US銘柄はドルで表示されるが、総投入額の合算表示がない。
- 推奨投入額→株数への換算表示がない（moomoo証券は端株対応）。

修正方針:
- 通知・ダッシュボードに「約XX株」の換算を追加する。
- ポートフォリオ全体のリスク配分サマリを追加する。

対象ファイル:
- src/notifier.py
- scripts/order_server.py


B-5. READMEに免責事項を明記する
-------------------------------
影響度: 中

現状:
- READMEには「実行規律補助システム」とあるが、初心者には候補や推奨投入額が買い指示に見える。

修正方針:
- README冒頭に以下を明記する。
  - 投資助言・利益保証ではない
  - 最終判断はユーザーが行う
  - 候補は「検討対象」であり注文指示ではない
  - 損失が出る可能性がある
- 通知文にも「買い候補」ではなく「検討候補」の表現を検討する。

対象ファイル:
- README.md
- src/notifier.py


B-6. API失敗時のフォールバック表示
----------------------------------
影響度: 中

現状:
- ダッシュボードのAPIエンドポイントが失敗した場合、チャート部分が空白のまま表示される。

修正方針:
- 各チャート・データセクションに「データ取得失敗」のフォールバック表示を追加する。

対象ファイル:
- scripts/order_server.py


優先度C: 品質・保守性
======================

C-1. order_server.py の HTML/CSS/JS 分離
-----------------------------------------
影響度: 高

現状:
- HTML/CSS/JS がすべて Python f-string 内にインライン（約1,500行）。
- 変更・レビューが困難で、テンプレートの見通しが悪い。

修正方針:
- Jinja2 テンプレートに分離する。
- CSS/JS は static ファイルに切り出す。
- Flask の標準テンプレート構成（templates/ + static/）を使う。

対象ファイル:
- scripts/order_server.py（分割元）
- templates/（新規）
- static/（新規）


C-2. モバイル対応の改善
-----------------------
影響度: 中

現状:
- テーブルは table-responsive（横スクロール）だが、カラム数が多く小画面では実質使いにくい。

修正方針:
- カード表示への切替やカラム省略を追加する。
- 小画面ではテーブルの重要列のみ表示し、詳細は展開式にする。

対象ファイル:
- scripts/order_server.py（テンプレート分離後）


C-3. 月次レポートの改善
------------------------
影響度: 中

現状:
- 月次レポート機能はあるが、システム改善の判断基準が弱い。

修正方針:
- 月次レポートに以下を追加する。
  - パターン別期待値（バックテスト・ペーパートレード実績）
  - 警戒モード時に停止した候補数
  - 損切り通知に従った場合の損失削減額
  - 資金サイズに対する月額コストの比率

対象ファイル:
- src/report_generator.py
- scripts/batch_monthly.py


C-4. LLM プロンプト肥大化ガード
---------------------------------
影響度: 中

現状:
- エントリー3件 + 保有5件 + ニュース複数件で、入力トークンが大きくなりコストが跳ねる可能性。
- トークン数はログに残るが上限ガードがない。

修正方針:
- プロンプト構築時にトークン数を推計し、上限を超える場合は情報を削減する。
- 同一日に複数回バッチを手動実行した場合のキャッシュも検討する。

対象ファイル:
- src/llm_advisor.py


C-5. ニュース取得の精度改善
----------------------------
影響度: 低

現状:
- Google News RSS のみ。銘柄名の一般名詞衝突（例: Apple）の可能性。
- 取得したニュースの日付チェックがなく、古いニュースが含まれる可能性。

修正方針:
- 銘柄名 + ティッカーの併用検索にする。
- ニュースの日付をチェックし、一定期間以上古いものは除外する。

対象ファイル:
- src/news_fetcher.py


C-6. アクセシビリティ改善
--------------------------
影響度: 低

現状:
- チャートの色依存（赤/緑）に対してパターンやラベルの代替手段がない。

修正方針:
- チャートにパターン（破線・点線等）やラベルの代替を追加する。

対象ファイル:
- scripts/order_server.py（テンプレート分離後）
